ModelDock Python 插件协议

定义 Python 模型插件怎样被安装、加载和执行，以及如何向 ModelDock 返回可校验、可展示的结果。本机与 SSH 节点使用同一套接口。

本文是插件协议的独立定义来源。仓库已提供 SDK/Worker 0.1.0 源码与随插件分发的 wheel；尚未发布独立 PyPI 包。当前实现范围见下表，后续扩展仍保留规划标识。系统调度见 技术方案，产品验收见 产品方案。
01

适用范围与责任边界

协议面向使用 Python 接入图像分类与目标检测模型的插件作者。文中的“必须”表示拟定的接入要求，“可选”表示不影响基础接入的扩展能力；未稳定的扩展接口可通过版本化评审调整。

主体负责内容
插件声明支持模型和依赖，实现模型加载、推理及前后处理，返回统一预测结果。
SDK / Worker校验调用与结果、解析节点文件、提供上下文、计时、取消检查和产物写入。
应用与节点控制器管理 uv 环境、SSH 与文件传输、任务队列、事件、报告与可视化。

插件不直接连接 SSH，不操作桌面控件，不自行安装依赖，也不向应用写入自定义控制消息。Python 虚拟环境用于依赖隔离；插件以节点用户权限执行，首版使用可信插件。

一个节点上的一个插件对应一个启用环境。插件可以支持多个模型；同一支持模型可以导入多套权重，形成不同模型实例。运行任务选择某个节点上的实例部署记录。

02

0.1.0 当前实现范围

能力0.1.0 实现与边界
基础接口load / predict / close；model 和 instance 为 dict，sample 为 Sample 数据类，context 为 Context。
模型配置model["config_data"] 为已加载 JSON 配置；instance["weight_path"]、["labels"]、["effective_parameters"] 为已解析任务数据。
分阶段接口继承 modeldock_sdk.StagedPlugin，SDK 提供 predict 包装与边界计时；普通插件仅统计预测调用总耗时。
可视化产物context.artifacts.write_bytes 登记有效 PNG/JPEG，最大 32 MB；Prediction 引用产物，应用按需预览。
运行与版本清单主版本 1，分类/检测结果版本 1；SDK/Worker 0.1.0，uv 0.13.6，参考插件运行 Python 3.12.14。
未开放部分GPU 参考环境、纯推理张量基准、视频及标注评估尚未开放；正式 JSON Schema 文件和独立接入 CLI 后续提供。

开发者可从 plugins/efficientnet 和 plugins/yolo 复制完整接入结构。修改 SDK 时，先通过 scripts/prepare_plugins.py 重建 wheel 和摘要锁定，再准备桌面资源；正常测试不解析或升级依赖。

03

插件目录与交付包

efficientnet/
  manifest.json                 # 插件清单与支持模型列表
  adapter.py                    # Python 入口
  configs/
    b0.json                     # 模型输入输出与预处理约定
    b1.json
  schemas/
    classification-params.json  # 参数与表单描述
  runtime/
    cpu/
      pyproject.toml
      uv.lock
      .python-version
  vendor/
    modeldock_sdk-<version>-py3-none-any.whl

交付格式为目录或 ZIP。ZIP 根目录直接包含 manifest.json；导入时由平台解包到临时位置并校验，不执行包内安装脚本。插件不携带 .venv、缓存、凭据和测试产物，权重默认独立管理。

清单中的文件路径均为插件根目录下的相对路径；运行方案的 Python 版本文件固定为其项目目录中的 .python-version。拒绝绝对路径、解析后越界的路径、危险符号链接及重复归档项。路径和普通文本使用 UTF-8。

平台记录完整包的 SHA-256。相同版本号但摘要不同的包必须提示差异，不静默替换正在使用的构件。SDK/Worker wheel 随兼容运行方案固定并纳入 uv.lock，保留可安装的相对路径。

字段类型 / 要求语义
schema_versionstring，必填，当前拟定为 "1"。清单主版本；不支持时拒绝安装。
idstring，必填，插件稳定标识。匹配 [a-z][a-z0-9_-]{0,63}，与显示名称分开。
name / versionstring，必填。显示名称；version 使用 MAJOR.MINOR.PATCH，预发布用标准后缀。
sdk_versionstring，必填。PEP 440 版本范围，例如 >=0.1,<0.2。
entrypointstring，必填。Python 模块:类，例如 adapter:Plugin；不是 shell 命令。
runtime_profiles非空数组，必填。可选运行方案及其依赖项目、平台和 Provider。
models非空数组，必填。插件实际实现的支持模型目录。
extensionsobject，可选，默认空。按命名空间组织的扩展，例如 com.example.metadata；不能改变核心字段含义。

插件、运行方案和模型标识使用同一标识格式。运行方案 id、模型 id 分别在插件内唯一。所有引用文件必须存在；版本约束与入口在安装阶段检查，模型实际加载在实例验证阶段检查。

未知清单核心字段在本草案中视为配置错误；可忽略的额外信息放入 extensions。增加核心必填字段、改变现有语义或引入不兼容接口时更新对应主版本。

05

支持模型、实例与参数描述

models[] 字段要求说明
id / name必填。模型稳定标识与显示名称，例如 efficientnet_b0。
task必填。首版为 classification 或 detection。
result_schema必填。对应 classification/1 或 detection/1；必须与 task 匹配。
weight_formats非空数组，必填。文件格式声明，例如 onnx；实际兼容性仍需加载检查。
config相对路径，必填。JSON 模型约定：输入尺寸/布局、颜色、归一化、输出与标签要求。
parameter_schema相对路径，必填。允许配置的模型参数与 UI 描述；无参数时提供空 properties。
capabilitiesobject，可选。timing_mode 默认 predict_total；pure_inference_benchmark 默认 false。
extensionsobject，可选。命名空间扩展，不改变标准结果含义。

模型实例提供权重、标签和用户参数；平台生成不可变的任务配置快照。参数按“模型默认值 → 实例覆盖 → 本次测试覆盖”合并，并用同一参数描述验证。未声明参数、类型错误和越界值必须报错。

首版参数描述采用 JSON Schema 的明确子集：object、string、number、integer、boolean、enum、properties、required、default、minimum/maximum、description 和 additionalProperties。平台不执行远程 $ref；不支持的校验关键字必须报错，避免静默忽略约束。

{
  "type": "object",
  "additionalProperties": false,
  "properties": {
    "top_k": {
      "type": "integer",
      "title": "显示类别数",
      "minimum": 1,
      "maximum": 100,
      "default": 5,
      "x-modeldock": {
        "scope": "predict",
        "advanced": false
      }
    }
  }
}

x-modeldock.scope 为 load 或 predict，默认 predict；load 参数在模型加载时生效，变更后通过新任务重新加载。advanced 只控制界面折叠。运行器仍需根据实际类别数检查 top_k，不因 schema 的上限允许值而接受超过类别数的配置。

设备、预热次数、正式次数、输入清单等平台测试参数不混入插件参数表单。插件配置只有在明确支持时才允许修改输入尺寸；固定尺寸模型应拒绝不兼容覆盖。

06

运行方案与 uv 依赖约定

runtime_profiles[] 字段要求
id必填，插件内唯一，例如 onnx-cpu。
project_dir必填，指向同时包含 pyproject.toml、uv.lock、.python-version 的目录。
platforms必填非空数组，首批为 windows-x86_64、linux-x86_64。
providers必填非空数组，本方案允许的执行后端；首批采用 ONNX Runtime Provider 名称。
extensions可选的命名空间元数据。

Python 版本文件应固定已验证的完整版本；pyproject.toml 的 requires-python 与之兼容。运行依赖、SDK/Worker 和本地 wheel 在锁文件中固定，依赖项目设置为运行依赖集合，不依赖全局 Python 包。

平台在安装、更新或修复阶段用 uv 创建候选环境并执行锁定同步，健康检查成功后启用。正常测试直接运行已有环境中的解释器，不触发 uv 解析或联网更新。

CPU 与 CUDA 等组合可以作为同一插件的不同运行方案，分别维护依赖项目与锁文件；一个节点只启用其中一个环境。插件代码不能自行修改环境，也不能发现 GPU 后静默改用未记录的 Provider。

跨 Windows/Linux 在目标节点本地创建环境，逐项检查原生包与 GPU 兼容。声明平台不等于通过验收；uv 不安装显卡驱动。在线及离线部署、回滚与环境清理由平台实现，见技术方案。

Python 接口与调用生命周期

# 接口草案：SDK 0.1.0：Context / Sample 已提供，model / instance 使用 dict。
class Plugin:
    def load(self, context, model, instance):
        # model: 支持模型声明与配置。
        # instance: 已解析的节点权重、标签和有效任务参数。
        ...

    def predict(self, sample, params, context):
        # 一次调用处理一个图片样本；返回标准 Prediction。
        context.raise_if_cancelled()
        ...

    def close(self):
        # 释放资源；应允许重复调用及部分初始化后的调用。
        ...
步骤调用约定
创建Worker 导入 entrypoint，创建无必填构造参数的插件对象；构造阶段不加载大型模型。
加载每个任务调用一次 load；验证权重、标签、参数与实际 Provider，失败则任务失败。
预热根据模式调用预测或分阶段接口；上下文 phase=warmup，结果不进入正式统计。
正式处理phase=measurement，按输入清单串行调用 predict；任务内复用同一已加载模型。
关闭正常结束、异常或协作取消时在 finally 中尽力调用 close；强制终止无法保证回调。

load 成功返回 None，predict 返回符合声明模式的 Python dict，close 返回 None。同一对象不并发调用。处理新模型实例时创建新的任务工作进程，实例间不共享未声明的模型状态。

插件不能在后台偷偷启动额外推理任务。确需子进程的库应由 Worker 所属进程组/Windows Job Object 管理，确保停止任务时不会遗留模型进程。

具备精细计时的插件可实现 SDK 的分阶段基类，由其提供 predict 包装；扩展点及同步要求见本协议的性能章节。

08

运行上下文与输入对象

对象 / 字段含义与使用约定
context.task_id / node_id当前任务与节点标识；本机和远端都存在。
context.phasewarmup 或 measurement；预热阶段不生成正式样本结果。
context.log(level, message, fields)结构化日志；不写凭据，大对象通过产物保存。
context.raise_if_cancelled()检查取消并抛出 SDK 专用取消异常；插件不得吞掉该异常。
context.read_image(sample)读取图片并按 EXIF 方向规范化，返回规范化后的尺寸及 RGB 图像。
context.artifacts任务产物写入器；生成 artifact_id，限制在任务产物目录中。
sample.sample_id / path / media_type / sha256稳定样本标识、节点本地已解析路径、媒体类型和内容摘要。
model["id"] / ["task"] / ["config_data"]当前支持模型及其不可变配置。
instance["weight_path"] / ["labels"] / ["effective_parameters"]节点本地权重、可选标签序列、已合并与校验的任务参数。

Python 进程内 path 可以是 pathlib.Path；跨进程传输由 SDK 处理。输入不包含 SSH 凭据或客户端临时路径。插件只读取本次任务提供的节点文件，不自行推断其他节点的路径。

规范化图片是应用预览和框坐标的共同基准：SDK 根据 EXIF 方向旋转/翻转后，以左上角为原点。简单插件可以使用自己的解码库，但必须遵守相同方向约定；无法提供可靠读取计时时相应分段为 null。

标签文件采用 UTF-8，每行一个类别名，行号从 0 对应 class_id，末尾换行不增加类别；中间空行报错。未提供标签时采用十进制 class_id 字符串作为显示名，平台不猜测训练类别。

统一结果与逐样本记录

Prediction 公共字段要求
result_schema / task必填，必须与支持模型声明一致。
sample_id必填，与当前输入样本完全一致。
image_size必填，{width, height}，均为正整数，使用方向规范化后的原图尺寸。
top_k 或 detections按任务类型提供且只提供对应核心结果。
artifacts可选，默认 []，仅引用上下文写入器已登记的产物。
extensions可选，默认 {}，命名空间扩展，平台可忽略。

结果必须能编码为 UTF-8 JSON，数值必须有限，不允许 NaN、Infinity、NumPy 标量/数组或 Torch Tensor 直接进入结果。数组与标量在插件中转换为原生 Python 类型。

图像分类结果 classification/1

{
  "result_schema": "classification/1",
  "sample_id": "img-0001",
  "task": "classification",
  "image_size": {
    "width": 640,
    "height": 480
  },
  "top_k": [
    {
      "class_id": 1,
      "label": "cat",
      "score": 0.93
    },
    {
      "class_id": 0,
      "label": "dog",
      "score": 0.05
    }
  ],
  "artifacts": [],
  "extensions": {}
}
  • top_k 按 score 从高到低排序，同分时按 class_id 升序；同一类别只出现一次。
  • class_id 是非负整数；提供标签时必须在标签序列范围内，label 必须与对应标签一致。
  • score 是单标签分类概率，范围 [0,1]；若模型输出 logits，插件按模型约定转换后返回。
  • 返回的前 K 类概率之和可以小于 1，不对截断后的 Top-K 再归一化；多标签分类需要未来单独的任务协议。
  • 有效分类必须至少有一个结果。请求 top_k 超过实际类别数应报参数错误，不静默改变配置。

应用可由此绘制 Top-K 条形图、批量预测摘要和模型并排结果。没有真实标签时，最高概率不表示分类正确率。

项目约定
坐标bbox_xyxy=[x1,y1,x2,y2]；原图像素浮点坐标，左上原点，右下边界按半开区间理解。
合法范围0 ≤ x1 < x2 ≤ width，0 ≤ y1 < y2 ≤ height；缩放、letterbox 和 padding 由插件还原并裁剪。
类别与分数class_id/label 规则同分类；score 为该检测结果的置信度，范围 [0,1]，不是整图准确率。
后处理插件完成约定的解码、阈值过滤和 NMS；平台不再叠加一次默认 NMS。
空结果未检测到目标时返回 detections=[]，这是有效预测，不是任务失败。
排序按 score 降序，再按 class_id 与坐标字典序稳定排序，便于复核及比较。

YOLO 配置必须明确导出版本、输出布局、是否内置 NMS、置信度计算和类别映射。SDK 拒绝非法框，插件应在输出前完成转换，不把模型输入坐标直接交给界面。

运行配置快照记录实际置信度、NMS 阈值与后处理版本。界面可以筛选已保存结果；降低到保存阈值以下或修改 NMS 需要重新测试，不能凭已有框恢复被过滤结果。

可视化与产物引用

标准数据应用侧可视化插件需要提供
分类结果Top-K 概率条形图、类别列表、批量摘要。类别、标签、概率及原图尺寸。
检测结果原图叠框、按类别着色、框与列表联动、筛选与同步缩放。规范原图坐标框、类别和置信度。
逐样本计时耗时趋势、分布图、分阶段堆叠图。使用 SDK 的计时能力声明与扩展点。
可选图像产物附件预览，例如解释性热图。由写入器登记的 PNG/JPEG 等图像产物。

原图与缩略图由平台按样本引用获取；插件无需烘焙检测框到图片中。标准坐标和类别数据用于交互，标注图片仅作为可选导出产物。

{
  "artifact_id": "<platform-generated-id>",
  "kind": "visualization",
  "media_type": "image/png",
  "sample_id": "img-0001",
  "title": "解释性热图"
}

产物写入器接受安全文件名、字节或任务内文件，返回引用并登记大小、摘要和节点位置。插件不得伪造 artifact_id 或返回任意外部 URL。首版不加载插件提供的 HTML/JavaScript 视图；新任务类型需要注册新的协议和界面组件。

SSH 节点先传回结构化预测和产物引用，应用按需获取图片，不把大图转成 Base64 混入事件。网络传输时间独立于推理计时。真实标注、混淆矩阵和误检漏检评估属于后续评估协议。

性能扩展与计时约定

capabilities.timing_mode 为 predict_total 或 staged。简单接入默认 predict_total：SDK 在调用外围记录 sample_total_ms，不能确认的细分阶段为 null。

staged 模式由 SDK 基类提供 predict 包装，插件实现以下扩展点；不通过插件自报任意数值生成正式性能指标。

class StagedPlugin:
    # load / close 与基础接口一致；predict 由 SDK 包装。
    def preprocess(self, image, params, context):
        ...  # image 是 SDK 解码后的图像与原始尺寸信息。

    def infer(self, inputs, params, context):
        ...

    def postprocess(self, outputs, sample, params, context):
        ...  # 返回标准 Prediction。

    def synchronize(self, context):
        ...  # 同步实际使用的设备队列；CPU 可空实现。
阶段要求
decode_msSDK 读取及 EXIF 方向规范化；简单插件自行解码时不可伪造该分段。
preprocess_ms输入转换；明确设备拷贝属于此阶段还是 infer，记录后保持一致。
inference_msSDK 在 infer 前同步排空旧工作，再开始计时，infer 后同步完成才停止计时。
postprocess_ms输出解析、排序、NMS、坐标还原，不含图片渲染/落盘。
sample_total_ms完整样本处理墙钟时间，不含 UI、产物写盘或网络。

纯推理模式仅在 staged 且 pure_inference_benchmark=true 时开放：先准备张量，在正式窗口只计 infer 与必要同步，结果校验在计时窗口外执行。预热结果不进入正式统计，插件不得把报告写盘等额外工作混入 infer。

后端类型、实际设备、同步方式、计时能力和输入缓存策略随任务保存。均值、P50/P95、吞吐量、失败样本分母与资源采样规则由平台统一计算，详见技术方案。

错误、日志与取消

错误代码默认范围处理
UNSUPPORTED_MODEL / INVALID_PARAMETERS加载或调用前。拒绝不支持的结构、配置或参数；要求修正后新建任务。
MODEL_LOAD_FAILED / DEVICE_UNAVAILABLE任务级。终止本次任务并记录加载或设备原因。
INPUT_DECODE_FAILED样本级。记录损坏/不支持图片，批量继续处理后续样本。
INVALID_PREDICTION样本级。记录字段或数值校验错误，不将该样本计为成功。
OUT_OF_MEMORY默认任务级。避免在设备状态不明时继续执行；由用户调整后新建任务。
PLUGIN_EXECUTION_FAILED默认任务级。未分类异常不默认视为可恢复；Worker 保存受控堆栈日志。
CANCELLED任务控制。由专用取消异常触发，保留已有结果，等待执行端确认终态。
PLUGIN_CRASH任务级。Worker 异常退出由监督进程登记，不依赖插件自行上报。

SDK 提供带 code、phase、scope、message、retryable 的 PluginError。可恢复的单项错误必须明确标为 sample 范围；其他异常由 Worker 按任务失败处理。retryable 只提示恢复可能性，不会使平台在网络超时后重复提交任务。

错误记录不包含凭据或大张量。Python 插件的 stdout/stderr 均作为日志捕获；Worker 使用独立控制通道，节点控制器的 SSH stdout 专用于结构化事件。插件不直接实现 JSON Lines 通信。

插件在解码、前处理、推理前后等适当边界检查取消，耗时循环周期性检查。不可中断的设备调用可能延迟响应；平台超时后终止任务进程组。close 应尽力释放资源，但强制终止时不保证执行。

版本兼容与接入检查清单

版本层次兼容规则
清单 schema_version决定清单字段与含义，不支持的主版本拒绝导入。
插件 version标识代码与模型支持变化，配合包摘要识别具体构件。
SDK 版本范围PEP 440 检查；0.x 阶段在显式范围内验证，不推断所有 0.x 版本兼容。
result_schema分类/检测各自版本化，不支持的结果模式在加载前拒绝。
进程消息 protocol_version由 Worker 与控制器维护，插件作者无需手写；跨节点保持可协商版本。

核心字段重命名、坐标/分数含义改变、必填参数增加或接口签名不兼容都需要对应协议主版本升级。可忽略元数据使用 extensions 命名空间。插件版本不能替代协议版本。

  1. 清单完整，支持模型与运行方案标识唯一，所有路径合法且存在。
  2. 在声明的 Windows/Linux 节点用锁文件完成环境准备与健康检查。
  3. 每个支持模型至少有成功样本、参数错误、权重不匹配和资源释放检查。
  4. 分类验证概率与标签；检测验证空结果、原图坐标、NMS 与稳定排序。
  5. 结果可编码为严格 JSON，无 Tensor/NumPy 对象和非有限数值。
  6. 检查预热排除、计时能力与 GPU 同步，未实现分段时明确返回 null。
  7. 损坏输入、可恢复样本异常、任务级异常和取消均按约定处理。
  8. 同一插件在本机与 SSH 节点使用相同 Python API，不包含节点地址或凭据。
  9. 权重与样本来源、参考结果和数值容差有记录；可视化无须理解原始张量。
