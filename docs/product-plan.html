ModelDock 产品方案

让模型开发者用 Python 接入模型，让测试人员在同一个 Windows 应用中完成本机或 SSH 远程推理、结果查看与性能比较。

本文描述产品目标与分阶段规划。0.1.0 已加入开发实现；安装包和原生验收状态以仓库 CI 为准，正式发布与人工验收独立。技术细节见 技术方案，插件作者参考 Python 插件协议。
01

产品定位与目标

ModelDock（模型坞）是面向模型开发者和测试人员的 Windows 桌面应用。应用采用 Tauri 构建交互界面，以 Python 插件承载模型能力，通过 uv 维护插件运行环境，并支持把插件部署到 SSH 远程节点。

首批场景为 YOLO 目标检测与 EfficientNet 图像分类。平台统一处理模型配置、文件输入、任务进度、可视化、性能统计和结果留存；模型插件实现加载、预处理、推理与后处理。

目标产品表现
降低接入成本新增已支持任务类型的模型时，主要编写 Python 适配器和模型声明。
减少环境维护安装、更新和修复运行环境归入插件管理，普通测试用户无需手动执行 Python 命令。
复用远程算力在同一工作台选择本机或 SSH 节点，使用节点上的 CPU 或经过验证的 GPU 环境。
形成可追溯结果每次测试保存配置快照、模型与插件版本、环境信息、结果和性能统计。

第一版聚焦推理测试。训练、微调、在线推理服务、分布式训练与插件商城不在首个完整版本的范围内。

03

用户与核心场景

用户需求完成标准
模型开发者把分类或检测模型接入应用按 SDK 实现适配器，声明依赖及支持模型，通过加载与结果协议检查。
测试人员测试新权重的效果、速度和稳定性导入权重与类别文件，完成单图或目录测试，导出可复核结果。
算法工程师对比模型、输入尺寸、设备与运行后端在已记录的测试配置下查看结果差异，明确不一致的比较条件。
远程算力使用者使用 Linux GPU 主机进行测试通过 SSH 部署插件，关联远端数据，查看进度并取回报告。

典型使用过程

  1. 开发者安装一个分类插件，插件声明支持 EfficientNet-B0、B1 等模型。
  2. 测试人员为 B0 导入两套业务权重与类别文件，创建两个模型实例。
  3. 在 Windows 本机执行单图检查，再选择 SSH 节点进行图片目录测试。
  4. 平台记录每次测试的模型、配置和节点信息，展示分类结果并导出报告。
04

产品对象与管理边界

对象定义关系
运行节点任务实际执行的位置：本机 Windows 或 SSH Linux 主机。管理连接、工作目录、设备能力及可达状态。
插件一组 Python 模型实现、依赖声明与支持模型目录。插件是部署和环境维护的管理单元。
支持模型插件明确支持的结构、任务类型、权重格式和默认配置。一个插件可以声明多个支持模型。
模型实例用户为某个支持模型配置的权重、类别与参数组合。同一支持模型可以对应多个业务模型实例。
模型部署记录某个模型实例在某节点上的权重及配置位置。测试前必须存在有效的节点部署记录。
测试任务在指定节点上，以配置快照运行指定模型实例。关联插件版本、输入清单、日志、指标与产物。
环境归属规则：一个节点上的一个插件只有一个启用中的运行环境。相同插件部署到两个节点时，各自维护环境。模型实例共用所属插件在该节点上的环境。

运行环境显示在插件的节点安装详情中，提供准备、检查和修复操作。应用不设置独立的全局“环境管理”主导航。节点离线不会删除其插件、模型或历史记录。

权重格式参考插件先支持 ONNX；格式由各插件声明。带独立依赖的 PyTorch 插件等。

平台只列出插件已声明并通过相应节点检查的模型与运行方式。ONNX 文件格式相同不代表预处理、输出语义和后处理相同；自定义权重必须与所选支持模型的约定匹配。

首次准备环境通常需要下载 Python 与依赖。环境和权重准备完成后，本机测试可以离线运行；远程测试仍需要能够连接对应 SSH 节点。完整离线安装包作为后续交付能力。

07

插件与模型接入流程

开发者的清单、Python 接口和结果约定见 Python 插件协议；本节说明产品侧操作流程。

插件开发者

  1. 选择已有任务协议，实现模型加载、推理与资源释放接口。
  2. 在插件清单中声明支持模型、权重格式、参数描述及兼容平台。
  3. 为运行方案提供 Python 版本约定、依赖项目及 uv 锁文件。
  4. 使用 SDK 检查输入输出和错误格式，打包为可导入插件包。

测试人员

  1. 导入插件包，查看插件来源、版本、支持模型和依赖要求。
  2. 选择目标节点安装；平台准备该插件的专属环境并执行健康检查。
  3. 从支持模型列表选择一个模型，导入权重、类别与必要配置。
  4. 执行加载验证，再进入测试工作台。
操作期望行为
切换 CPU/GPU 运行方案插件在该节点切换到一个新的环境配置；完成检查后启用，旧环境在切换完成后清理。
更新插件显示版本与依赖变化，等待运行任务结束后更新；检查失败时保留可用版本。
修复环境按锁文件重建，不修改权重、类别文件和历史记录。
卸载某节点上的插件清理该节点插件代码及专属环境；权重和测试记录保留，实例显示不可运行。
同一模型导入不同权重形成不同模型实例，共用插件运行环境，分别记录权重指纹。

插件包包含可执行 Python 代码，导入页说明这一性质及运行位置。首版用于可信插件，运行环境隔离用于依赖管理，不承诺隔离插件对用户文件或网络的访问。

08

SSH 远程测试体验

  1. 新增 SSH 节点，配置主机、端口、用户、身份验证方式和可写工作目录。
  2. 首次连接核对主机指纹，检查主机平台、Python 准备条件、磁盘和设备能力。
  3. 选择插件并安装到该节点，查看部署阶段、下载进度和失败原因。
  4. 选择上传本机文件，或关联该节点已有的权重与数据目录。
  5. 启动测试，持续查看进度、日志和按需预览。
  6. 任务完成后下载报告及所需产物；大文件可保留远端，状态显示是否已取回。
连接状态与任务状态分别显示。SSH 断开时提示“节点不可达，任务状态待确认”。已提交的任务可能仍在运行；应用不会自动重复提交。重连后按任务编号恢复查询。

首版支持的远程节点需要通过后台任务存活检查。任务可在连接断开后继续运行，但主机重启或工作进程崩溃后的自动续算不属于首版承诺；系统恢复后应报告中断并允许新建重试任务。

移除节点仅删除应用中的连接配置，不会自动删除远端模型、任务或结果。远端清理由用户在节点详情中明确执行，并显示将清理的内容。

09

测试模式、指标与比较

模式输出限制
单图测试检测框、类别、置信度、图片级耗时。用于加载与效果检查，不把单次耗时当作稳定性能结论。
图片目录测试逐项结果、进度、成功与失败统计、结果图片。单项失败可以继续处理；全部失败则任务失败。
性能测试预热后统计平均值、P50、P95 和吞吐量。固定输入、设备、后端与并发配置，明确样本数。
精度评估（后续）分类 Top-1/Top-K；检测 mAP@0.5 与 mAP@0.5:0.95。要求标注、类别映射和数据集格式明确；失败样本不得被静默忽略。

默认性能配置拟定为预热 10 次、正式测量 100 个样本执行，batch=1、单工作进程。配置可调整；重复使用输入时报告唯一图片数、执行次数和缓存策略。

指标呈现规则
模型推理耗时仅统计推理阶段，GPU 后端按要求同步；插件未提供可靠分段能力时显示“不支持”。
图片处理耗时读取/解码、预处理、推理与后处理分段记录，给出统一边界。
处理吞吐量根据实际处理时间窗口计算成功样本数/秒，独立于上传和下载。
任务完成耗时分别列出排队、准备、处理、产物写入和传输耗时。
资源占用记录采样范围内的内存峰值；支持时记录显存及设备信息。
精度无标注时显示“未评估”，不显示猜测准确率。

比较页至少显示输入尺寸、权重指纹、精度类型、运行后端、设备、线程、批大小、插件版本及数据清单指纹。条件不一致时给出差异标识。外部 GPU 负载等未受控因素列为测试条件限制。

10

状态与异常反馈

对象主要状态恢复入口
插件节点安装未安装、准备中、检查中、可用、失败、更新中、卸载中。查看阶段日志、重试、修复；运行任务期间阻止破坏性变更。
模型部署未配置、待检查、可用、不兼容、文件缺失。重新选择权重、修正类别或配置、再次验证。
节点未知、连接中、在线、不可达。重新连接、检查认证及主机指纹。
任务排队、准备、运行、请求取消、成功、部分失败、失败、已取消。查看结果与原因；重试生成新任务并关联原记录。

错误信息包含发生阶段、可读原因和下一步操作。例如依赖下载失败提供重试入口；模型输出不匹配指出模型约定；显存不足建议检查设备与模型配置。用户主动停止后，界面保持“请求取消”直到执行端确认终态。

批量任务中，部分样本失败时保留成功结果并标记“部分失败”，报告失败清单。中途取消仍保留已完成样本，完整性标为未完成。

验收标准

编号场景验收结果
P-01干净的受支持 Windows 测试机安装并启动应用，无需用户预装 Python；首次在线准备有明确阶段提示。
P-02插件支持模型目录插件详情列出 EfficientNet-B0/B1 或 YOLOv8n/s 等已声明模型、任务、格式与兼容限制。
P-03同节点安装两个插件各自拥有独立环境，插件环境修复不影响另一插件，也不删除模型和历史。
P-04导入两套分类权重创建两个模型实例、独立类别映射，在同一插件环境中加载与测试。
P-05分类及检测测试参考样本结果与参考实现按约定容差一致；检测框映射回原图坐标。
P-06批量包含损坏图片继续执行其他图片，逐项记录错误，终态与成功/失败计数一致。
P-07性能与报告预热不混入正式统计；报告包含计时边界、样本数、环境及配置快照；可导出 JSON/CSV。
P-08SSH 节点部署在经过支持检查的 Linux 节点安装插件，复用已有远端权重/数据并完成测试。
P-09SSH 中断与恢复任务继续运行；重连获取同一任务的状态与结果，没有重复执行；不支持存活的节点被明确识别。
P-10停止与失败恢复取消经执行端确认；工作进程异常有明确终态；重新测试创建新记录。
P-11文件和凭据节点身份验证信息不进入报告与普通日志；输出只写入配置的数据目录。
P-12离线复用已有环境和权重的本机测试不要求联网，不自动触发依赖更新。

测试覆盖固定版本的 Windows 10/11 x64、选定 Linux x86_64 发行版和至少一个已验证 NVIDIA 运行方案。具体版本、最低硬件配置及性能目标在实现阶段通过基线测试确定，当前不承诺通用 FPS 或任意驱动兼容。

12

交付阶段与待确认项

阶段交付内容进入下一阶段的条件
M0：协议与接入验证插件清单、SDK、两种结果协议及 uv 环境验证。两个参考插件能被相同运行器加载，依赖可重建。
M1：本机测试闭环Windows 应用、插件与模型管理、单图/批量/性能、历史与导出。通过 P-01 至 P-07、P-10 至 P-12 的本机部分。
M2：远程节点闭环SSH 部署、数据关联与传输、后台任务、重连与结果取回。通过 P-08、P-09 及远程停止、失败恢复检查。
M3：首个完整版本稳定性、选定 GPU 方案、安装包与使用说明。完整验收矩阵通过，已知限制被记录。
后续迭代标注评估、视频输入、更多任务、完整离线包与插件分发。按实际使用需求确定顺序。

实施前仍需确定：参考权重与样本的可分发来源、最终 YOLO 输出约定、首批 GPU/驱动组合、SSH 认证实现与受支持 Linux 版本，以及结果保留和缓存清理策略。这些不改变既定的插件归属与节点执行模型。
